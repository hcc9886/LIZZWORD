# LIZZWORD 做成一款软件（App）的建议

> 版本：2026-11-22 · 面向：把现有静态站打包成 iOS / Android / 桌面应用
> 现状：31 本书、57,000+ 词、22 字段深度词条、300+ 件 Lizz 装扮、拼装/计划/教师端已就绪
> 全部代码无第三方依赖、无 CDN、`file://` 可跑，天然适合 WebView 壳

---

## 0. 一句话路线

**先做「离线可用的 WebView 壳 + 内购」，再补服务端（账号/同步/事件/支付校验），最后做「教师端 + 家庭版」两条 B 端线。**
不要一上来重写成原生——现在的 22 字段词库和交互逻辑是最大资产，重写等于把资产归零。

---

## 1. 打包方式选型

| 方案 | 适用 | 优点 | 代价 |
|---|---|---|---|
| **Capacitor**（推荐） | iOS + Android | 复用 100% 现有代码；插件生态全（IAP、通知、文件）；可逐步加原生能力 | 需 Xcode / Android Studio 打包 |
| Cordova | 老项目 | 同上 | 生态老化，新插件少 |
| Tauri | 桌面（Mac/Win） | 体积小、性能好 | 移动端支持弱 |
| React Native / Flutter 重写 | 团队有原生能力 | 体验最好 | 全部重写，词库逻辑迁移成本高，不建议现在做 |
| PWA + 商店封装 | 快速上线 | 零改造 | iOS 上架受限；无 IAP 便利 |

**建议**：Capacitor 打 iOS/Android；桌面用 Tauri 或直接 Electron；三端共用同一份 `www` 目录（就是现在的仓库根）。

---

## 2. 数据与离线（最关键）

现状：分片约 300MB（gzip 后每本 5–12MB），一次打开一本书最多 300 多个分片。
App 不能像网页那样边用边拉，必须**本地打包词库 + 增量更新**。

建议：

1. **首装内置词库**：把 `books/prepared`、`books/manifest.js`、`books/manifest-hashes.json` 打进安装包。
   - iOS 安装包上限约 200MB（可申请更大），Android 也一样；必要时首装只带 TOP 12 本（约 80MB），其余按需下载。
2. **增量更新**：客户端拿 `manifest-hashes.json` 与服务端比对，只重下 sha1 变化的分片。
3. **SQLite 替 IndexedDB**：Capacitor 用 `@capacitor-community/sqlite` 存 `sentence_cache`、`assembly_queue`、学习记录，比 IndexedDB 稳、可备份、可导出。
4. **词库索引**：为每个词条建 `word → (bookId, shard, offset)` 索引表，点开单词 O(1) 定位，不再整片加载。

## 3. 内购与权益（必须走平台规则）

| 平台 | 支付 | 注意 |
|---|---|---|
| iOS | **StoreKit / IAP** | 数字内容必须走 IAP，抽成 15%（小企业）/30%；不能引导站外支付 |
| Android | **Google Play Billing** | 同上；可配置试用与促销码 |
| 桌面/Web | Stripe / 微信支付宝 | 不受抽成，但需主体资质与备案 |

权益模型（已在代码里预留 `pro` / `team`）：

| 档位 | 权益 |
|---|---|
| 免费 | 每天 50 新词、零基础整本、任选 1 本完整学完、22 字段全可见 |
| Plus | 不限新词、全部 31 本、计划、离线整书包、跨端同步、跟读评分 |
| Pro | Plus + 完整词条深度扩展 + 自定义词书 + 造句批改 |
| Team | Pro + 教师端（建班/布置/完成率/CSV 导出） |

**内测码已内置**（`books/lizz/entitlements.js`）：
`wansuiwansuiwanwansui1313113`（永久）、`nulixuexiya2027`（一年）、`lizzzhaohaoyon!!!`（一月）。

上线前必须补：
1. 服务端写 `profiles.plan`（前端只读，防改本地）；
2. App Store / Play 的订阅组、促销码、退款回调；
3. 隐私政策、用户协议、未成年人条款。

## 4. 账号与同步

- 现在：Supabase 已有 `init.sql` / `events.sql`（`profiles`、`learning_events`、`event_funnel` 视图）。
- App 里建议：
  - 邮箱/Apple/Google 登录三选一（Apple 登录是 iOS 上架硬要求，若提供第三方登录）；
  - 学习数据走「本地优先 + 后台增量同步」，冲突用「最近写入优先 + 词级合并」；
  - 事件流每 20 条批量上报，做漏斗：`trial_start → paywall_view → checkout_start → purchase_success`。

## 5. 必须补的原生能力

| 能力 | 用途 | 插件 |
|---|---|---|
| 本地通知 | 每日提醒、连续打卡 | `@capacitor/local-notifications` |
| 文件读写/分享 | 导出 CSV（教师端）、明信片 | `@capacitor/filesystem` + `share` |
| 安全存储 | 登录 token | `@capacitor/preferences`（或 Keychain 插件） |
| 后台下载 | 整本书离线包 | 自建下载队列（分片 + 断点续传） |
| 语音 | 已有 `speech.js`（Web Speech），App 里建议改用原生 TTS | `@capacitor-community/text-to-speech` |
| 语音识别 | 跟读评分 | iOS `SFSpeechRecognizer` / Android `SpeechRecognizer` 插件 |

## 6. 体验与性能

1. **首屏 <1.5s**：App 启动先读本地索引 + 主表，不走网络；`index.html` 600KB+，建议拆 CSS 与注册表（已部分用 manifest）。
2. **分片懒加载**：已实现「前 20 片立即、其余空闲补齐」；App 里改成「按需 + 后台预取下一本」。
3. **包体优化**：SVG 装扮全部内联（无图片），这块已经很好；词库分片可再 gzip 一层（实测压缩比约 4:1）。
4. **崩溃兜底**：分片解析失败要能回退到内置包，不能白屏（现有 `loadErrorBanner` 可复用）。

## 9. 长期方向（做完 90 天之后）

1. **家庭版**：一次订阅 3 账号，家长看进度。
2. **班级/学校 B 端**：教师布置词书、看班级完成率、导出成绩、批量导入学生。
3. **AI 造句批改**（服务端模型）：用目标词造句，返回语法与搭配建议。
4. **自适应难度**：Elo 简化版，按答题动态调词序。
5. **词书继续扩张**：现在 31 本，建议按「考试 + 专业 + 配套（词根/搭配/易混）」三条线各补 5–10 本。

---

## 10. 不建议做的事

1. 不要重写成原生再迁移词库——22 字段结构复杂，迁移风险高。
2. 不要在前端硬编码权益开关；一定要服务端校验。
3. 不要把付费内容放在公开静态目录；用签名 URL 或打包加密。
4. 不要为「省包体」砍掉深度字段——22 字段正是付费理由。
5. 不要在 iOS 引导用户去站外支付（会被拒审）。
